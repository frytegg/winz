## Tooling baseline

Project wins: first run the tools the project declares (pyproject `[dependency-groups]` and `[tool.*]`, uv.lock, `.pre-commit-config.yaml`, CI) at their pinned versions and with their configs. Use the commands below only to fill gaps. The versions were current on 2026-09-23: re-check each release before a run, pin the exact version, record it in `tool_versions`, and save raw output under `.harden/tools/`. Detectors never run on `.` (detection step 4; eval-v2-calibration E02-F08): `F` below holds the in-scope `.py` and `.pyi` files, `mapfile -t F < <(grep -E '\.pyi?$' .harden/tools/inscope.txt)`, plus the `.ipynb` files for Ruff, which lints notebooks; Ruff also gets `--force-exclude`, so the project's excludes still apply to files passed by name. Tools that import the project (pytest, mypy, pyright, deptry) run in the project environment (`uv run`), not through `uvx`. On Windows call `python`; inside WSL call `python3`. rope is set up under PY-09 and the mutation tools under PY-34.

```
uvx ruff@0.16.8 check --force-exclude --no-fix --output-format concise --select <codes> "${F[@]}" > .harden/tools/ruff.txt
uvx ruff@0.16.8 check --force-exclude --statistics --select <codes> "${F[@]}"
uv run mypy --check-untyped-defs src/          # or the project's pyright / basedpyright
uvx vulture@2.16 src/ --min-confidence 90 --sort-by-size
uvx deadcode@2.4.1 "${F[@]}" --fix --dry        # preview only
uv run deptry .                                # inside the project venv (PY-18)
uvx pip-audit@2.10.1 --locked .
uv lock --check
uvx griffe@2.3.0 check <pkg> --against <base-ref> --search .
uv run coverage run --branch -m pytest && uv run coverage report
uv run pytest --collect-only -q
```

### PY-01 — Run the project's pinned tools first; pin every extra tool exactly
- **Rule:** Run the linters, type checkers and test runner the project declares, at its pinned versions and with its config, through its environment (`uv run`). Run a tool the project lacks with `uvx <tool>@<x.y.z>`, except tools that import the project, which run in the project environment. Never add an audit-only tool to pyproject, a lock file or pre-commit, and never run an unpinned or `latest` version.
- **Detect:** Read pyproject `[dependency-groups]` and `[tool.*]`, uv.lock, `.pre-commit-config.yaml` and CI for tool pins; record every version actually run; a before/after comparison made with different tool versions is not comparable.
- **Not when:** Ruff 0.16.0 (2026-07-23) raised the default rule set from 59 to 413 rules, so a newer ephemeral Ruff on a project with no explicit `select` reports rules the project never enabled: pass `--select` explicitly (PY-02). mypy's docs ask that everyone run the same mypy version.
- **Tier:** T2 · **Class:** report-only · **Fix risk:** low · **Grade:** A
- **Source:** [uv: Using tools](https://docs.astral.sh/uv/guides/tools/) (Astral, 2026); [Ruff CHANGELOG](https://raw.githubusercontent.com/astral-sh/ruff/main/CHANGELOG.md) (Astral, 2026); [Using mypy with an existing codebase](https://mypy.readthedocs.io/en/stable/existing_code.html) (mypy 2.3.1 docs, 2026) · dossier: lang-python T21-F01, T21-F10; polyglot-tooling T25-F03

### PY-02 — Detect with an explicit Ruff rule list; report configuration changes
- **Rule:** For detection, pass `--select` on the command line and never edit the project's Ruff configuration. Treat the 0.16 default set as a vendor-curated start that mixes correctness rules with import sorting (I001) and pyupgrade (UP) rewrites, and add the high-value rules it omits: B904, RUF006, S113, S301, S307, S506, S602, S608, PGH003, PGH004, PLW0603. Run C901, PLR0911–PLR0915 and ERA001 as report-only worklists. A Ruff pin, an explicit `lint.select` (never a bare `ALL`) or a Ruff upgrade is a report item.
- **Detect:** Look for a Ruff pin, `select = ["ALL"]`, `extend-select` or no `select`; `ruff check --force-exclude --statistics "${F[@]}"` sizes the backlog; `ruff check --force-exclude --select PGH004,RUF100 "${F[@]}"` finds blanket and stale suppressions.
- **Not when:** A legacy repo may keep the pre-0.16 set `["E4", "E7", "E9", "F"]` and ratchet up. After the 0.16 upgrade, practitioners reported 2,900 new errors in one codebase and 100+ unfixable errors in another under 10k LOC (HN, 2026). Astral published no per-rule false-positive rates, only that "many of these rules catch severe issues".
- **Tier:** T2 · **Class:** report-only · **Fix risk:** low · **Grade:** A
- **Source:** [Default Rules](https://docs.astral.sh/ruff/default-rules/) (Astral, 2026); [The Ruff Linter](https://docs.astral.sh/ruff/linter/) (Astral, 2026); [Ruff v0.16.0](https://astral.sh/blog/ruff-v0.16.0) (Westbrook, Astral, 2026); [HN maratc](https://news.ycombinator.com/item?id=49081177) (2026); [HN apelapan](https://news.ycombinator.com/item?id=49057504) (2026) · dossier: lang-python T21-F01; eval-v2-calibration E02-F08

### PY-03 — Ratchet type checking; never flip a codebase to strict at once
- **Rule:** Start from mypy `check_untyped_defs = true` or pyright's default "standard" mode, then follow mypy's documented order: warn_unused_configs, warn_redundant_casts, warn_unused_ignores, strict_equality, check_untyped_defs, disallow_subclassing_any, disallow_untyped_decorators, disallow_any_generics, disallow_untyped_calls, disallow_incomplete_defs, disallow_untyped_defs, no_implicit_reexport, warn_return_any, extra_checks. Keep legacy debt visible with per-module overrides, pyright `strict` paths or a basedpyright baseline; avoid a global `ignore_missing_imports`. Report strictness changes; do not make them.
- **Detect:** `uv run mypy --check-untyped-defs src/` and count errors; `basedpyright --writebaseline`; grep the config for a global `ignore_missing_imports = true`; check that CI pins the checker version. By default mypy does not check the bodies of unannotated functions.
- **Not when:** mypy could have prevented 15% of defects in 210 Python projects, a lower bound (TSE 2021), and 78.3% of commits were made despite type errors (9,655 projects, ESEC/FSE 2022). Practitioners report that many findings are annotation bugs and that untyped libraries produce ignorable noise; mypy and pyright disagree on edge cases; ty's maturity rests on one practitioner report.
- **Tier:** T2 · **Class:** report-only · **Fix risk:** low · **Grade:** A
- **Source:** [Khan et al., TSE 2021](https://api.openalex.org/works/doi:10.1109/tse.2021.3082068) (2021); [Di Grazia & Pradel, ESEC/FSE 2022](https://api.openalex.org/works/doi:10.1145/3540250.3549114) (2022); [Using mypy with an existing codebase](https://mypy.readthedocs.io/en/stable/existing_code.html) (mypy, 2026); [Pyright configuration](https://raw.githubusercontent.com/microsoft/pyright/main/docs/configuration.md) (Microsoft, 2026); [basedpyright baseline](https://docs.basedpyright.com/latest/benefits-over-pyright/baseline/) (basedpyright, 2026) · dossier: lang-python T21-F10

## Autofix safety

### PY-04 — Ruff safe fixes: one rule id per commit, previewed and gated
- **Rule:** Auto-apply only fixes Ruff labels safe, excluding the codes in PY-05 and the logic codes F632 and F811, which follow PC-10 (T1 per rule only after a manual sample of hits shows no false positives, otherwise T2): one rule id per commit, from a clean tree, previewed with `--diff`, with the full test suite after each commit. Reject a commit that touches tests or adds a suppression. Never run `--unsafe-fixes` or a broad `extend-safe-fixes` unattended, and never delete or skip a test to silence a diagnostic.
- **Detect:** `ruff check --force-exclude --select <CODE> --diff "${F[@]}"`, then `ruff check --force-exclude --select <CODE> --fix "${F[@]}"`; afterwards `git diff --stat`, `git diff --name-only | grep -E '(^|/)tests?/'` and the test suite.
- **Not when:** Ruff defines unsafe fixes as those that may change runtime behaviour, but its safe labels are sometimes wrong, even on stable default rules: F541 (#18807, open), F504 with side-effecting arguments (#18806), C408 (#16234) and RUF015 (#6148). The tracker's 276 issues labelled both `fixes` and `bug` (reproduced 2026-09-23) are fix-related bug reports at every tier (preview and unsafe fixes, infinite loops, syntax errors Ruff reverts itself), not counts of safe-label failures. Practitioners report that 10–30% of a new rule set's findings are autofixable, and one reports about 90% (HN, 2026); either way, apply one rule id at a time. One agent was seen "fixing" a rule by deleting the test (HN, 2026).
- **Tier:** T0 · **Class:** structural · **Fix risk:** medium · **Grade:** A
- **Source:** [The Ruff Linter: fix safety](https://docs.astral.sh/ruff/linter/) (Astral, 2026); [Ruff issues labelled fixes and bug](https://github.com/astral-sh/ruff/issues?q=is%3Aissue+label%3Afixes+label%3Abug) (GitHub, 2026); Ruff issues [#18807](https://github.com/astral-sh/ruff/issues/18807), [#18806](https://github.com/astral-sh/ruff/issues/18806), [#16234](https://github.com/astral-sh/ruff/issues/16234) and [#6148](https://github.com/astral-sh/ruff/issues/6148) (GitHub); [HN biorach](https://news.ycombinator.com/item?id=49057319), [HN vasachi](https://news.ycombinator.com/item?id=49057474), [HN apelapan](https://news.ycombinator.com/item?id=49057504) and [HN mikeydiamonds](https://news.ycombinator.com/item?id=49057551) (2026) · dossier: lang-python T21-F02, T21-F01; autofix-trust G105-F02, G105-F05, G105-F07, G105-F15; dead-code-tools T07-F21; eval-v2-calibration E02-F08

### PY-05 — Fixes that always go to hunk-by-hunk review
- **Rule:** Keep these out of T0; apply them one code per commit after reading every hunk, then run the tests: F541 (fix can turn a string into a docstring, #18807, open), F504 with side-effecting arguments (#18806), C408 (#16234), RUF015 (`list(...)[0]` to `next(iter(...))` turns IndexError into StopIteration), F841 (may delete attached comments), B006 (labelled unsafe), PLW1514 (always unsafe), PD002 (`inplace=True` to reassignment) and NPY201 (removed NumPy 2 APIs), each of the last two followed by a golden-output check (PY-39). Treat every preview-rule fix the same way: RUF055's "safe" fix changed an assertion's result (#27024, 2026).
- **Detect:** `ruff check --force-exclude --unsafe-fixes --diff --select <CODE> "${F[@]}"` for review only; `ruff check --force-exclude --select PD002,NPY201 --diff "${F[@]}"`; after each code, the tests and the golden check.
- **Not when:** PD002's rewrite changes aliasing: a caller that passed a DataFrame in and relied on `inplace=True` mutating it no longer sees the change. PDEP-8's `inplace` deprecation had not shipped in pandas 3.0.0–3.0.6, so PD002 is a preference, not a migration.
- **Tier:** T1 · **Class:** structural · **Fix risk:** medium · **Grade:** A
- **Source:** [Ruff issue #27024](https://github.com/astral-sh/ruff/issues/27024) (GitHub, 2026); [F841 unused-variable](https://docs.astral.sh/ruff/rules/unused-variable/) (Astral, 2026); [B006 mutable-argument-default](https://docs.astral.sh/ruff/rules/mutable-argument-default/) (Astral, 2026); [PLW1514 unspecified-encoding](https://docs.astral.sh/ruff/rules/unspecified-encoding/) (Astral, 2026); [Ruff PD002](https://docs.astral.sh/ruff/rules/pandas-use-of-inplace-argument/) (Astral, 2026); [PDEP-8](https://pandas.pydata.org/pdeps/0008-inplace-methods-in-pandas.html) (pandas, 2023) · dossier: lang-python T21-F02, T21-F03, T21-F13, T21-F22; data-pipelines-notebooks G109-F06, G109-F21, G109-F05; eval-v2-calibration E02-F08

### PY-06 — Check for runtime annotation consumers before TC, FA or UP annotation fixes
- **Rule:** Before applying TC001–TC003, FA100/FA102 or UP006/UP007/UP045 fixes, search for code that evaluates annotations at runtime: pydantic, SQLAlchemy 2 `Mapped[]`, FastAPI, typer, attrs/cattrs, `get_type_hints`, DI frameworks. Where any exist, leave those modules alone and report the settings the project would need (`runtime-evaluated-base-classes`, `runtime-evaluated-decorators`, and `lint.pyupgrade.keep-runtime-typing` below Python 3.10). Confirm `project.requires-python`, from which Ruff derives its target version.
- **Detect:** `rg -n 'BaseModel|Mapped\[|DeclarativeBase|@inject|get_type_hints|typer|cattrs|@validate_call'`; `ruff check --force-exclude --select TC,FA,UP --diff "${F[@]}"`; after applying, import every module and run the tests.
- **Not when:** Pure libraries and CLIs benefit from TC moves. FA100/FA102/UP006/UP007/UP045 are in the 0.16 defaults with fixes labelled unsafe in the risky cases; TC001–TC003 are not defaults. How PEP 649/749 (Final, 3.14) changes this risk was not verified; Ruff issues #7866 and #14140 are open.
- **Tier:** T1 · **Class:** structural · **Fix risk:** high · **Grade:** B
- **Source:** [TC002 typing-only-third-party-import](https://docs.astral.sh/ruff/rules/typing-only-third-party-import/) (Astral, 2026); [FA100](https://docs.astral.sh/ruff/rules/future-rewritable-type-annotation/) (Astral, 2026); [Ruff settings](https://docs.astral.sh/ruff/settings/) (Astral, 2026); [Ruff issue #7866](https://github.com/astral-sh/ruff/issues/7866) (2023) · dossier: lang-python T21-F12; eval-v2-calibration E02-F08

### PY-07 — Never apply PD010, PD011 or NPY002 messages as equivalences
- **Rule:** Report PD010 (pivot/unstack to pivot_table), PD011 (`.values` to `.to_numpy()`) and NPY002 (legacy `np.random` to `Generator`) hits; do not rewrite them by hand as if the rule message ("provides same functionality") were true. Ruff offers no autofix for these three, so the risk is an agent applying the message.
- **Detect:** `ruff check --force-exclude --select PD,NPY,PLW0177 --no-fix --output-format concise "${F[@]}"`; for each PD011 hit, check whether the data is tz-aware datetime, categorical or pandas 3 `str`; for each PD010 hit, run `df.duplicated([index, columns]).any()` on real data.
- **Not when:** pivot raises on duplicate index/column pairs while pivot_table silently averages them; for tz-aware data `.values` gives UTC datetime64 while `.to_numpy()` gives an object array of aware Timestamps; `Generator` cannot reproduce legacy random streams, and scikit-learn's `random_state` accepts only None, an int or a `RandomState`. Most PD rules are style-only.
- **Tier:** T2 · **Class:** report-only · **Fix risk:** high · **Grade:** A
- **Source:** [Ruff rules index](https://docs.astral.sh/ruff/rules/) (Astral, 2026); [pandas.DataFrame.pivot](https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.pivot.html) (pandas, 2026); [pandas.Series.values](https://pandas.pydata.org/docs/reference/api/pandas.Series.values.html) (pandas, 2026); [Random Generator: what's new or different](https://numpy.org/doc/stable/reference/random/new-or-different.html) (NumPy, 2026); [check_random_state](https://scikit-learn.org/stable/modules/generated/sklearn.utils.check_random_state.html) (scikit-learn, 2026) · dossier: data-pipelines-notebooks G109-F06, G109-F15; eval-v2-calibration E02-F08

### PY-08 — Run the formatter only where the project enforces it, on the item's files
- **Rule:** Run `ruff format` or Black only when the project already enforces that formatter, at its pinned version, only on the `.py` files the item touches (`ruff format <files>`), in a `style:` commit placed immediately before the item's semantic commit. A whole-repo format run is a T1 item that needs its own explicit approval (PC-11) and runs only after it. Adopting a formatter is a report item: one dedicated commit with no semantic change, recorded in `.git-blame-ignore-revs`.
- **Detect:** `ruff format --check --force-exclude "${F[@]}"` or `black --check "${F[@]}"`; before committing, `git diff --name-only` lists only the item's files; with ruff format, check that no conflicting lint rule is enabled: W191, E111, E114, E117, D203, D206, D300, Q000–Q004, COM812, COM819, and ISC002 without ISC001 and `allow-multiline = false`.
- **Not when:** Since 0.16 the Ruff formatter also formats Python code blocks in Markdown files by default, so a directory-wide run can touch docs. Formatters destroy intentional alignment. Ruff formats more than 99.9% of lines the same as Black on Django and Zulip.
- **Tier:** T0 · **Class:** structural · **Fix risk:** low · **Grade:** A
- **Source:** [The Ruff Formatter](https://docs.astral.sh/ruff/formatter/) (Astral, 2026); [Introducing Black to your project](https://black.readthedocs.io/en/stable/guides/introducing_black_to_your_project.html) (Black 26.5.1, 2026); [Ruff CHANGELOG](https://raw.githubusercontent.com/astral-sh/ruff/main/CHANGELOG.md) (Astral, 2026) · dossier: lang-python T21-F23; autofix-trust G105-F08; eval-v1-calibration E01-F02; eval-v2-calibration E02-F08

## Refactoring engines

### PY-09 — Drive rename, move, extract, inline and change-signature through rope
- **Rule:** Apply Python rename, module and global moves, extract method/variable, inline and change-signature with the rope 1.14.0 library API. Open the project with `Project('.', ropefolder=None)` so no `.ropeproject` folder is written, read `changes.get_description()` before `project.do(changes)`, and always pass an `unsure` callback that logs each occurrence; abort and report when the log is not empty, because rope ignores unsure occurrences when `unsure` is None.
- **Detect:** Install rope in a throwaway venv under `.harden/tools/` (`python -m venv .harden/tools/rope`, activate it, `pip install rope==1.14.0`; PF-21); pass `unsure=lambda occ: log.append((occ.resource.path, occ.offset)) or False`; compare basedpyright `textDocument/references` before and after.
- **Not when:** In one fixture run (Windows, 2026), ChangeSignature missed a call made through `getattr`, which failed at runtime; move global needs an existing destination and rewrites callers to fully qualified imports; `docs=True` renames matching strings and comments textually. rope's inference is weakest on duck-typed, getattr-heavy or framework-magic code (Django, pytest fixtures).
- **Tier:** T1 · **Class:** structural · **Fix risk:** medium · **Grade:** A
- **Source:** [rope overview](https://rope.readthedocs.io/en/latest/overview.html) (python-rope, 2026); [rope rename.py docstring](https://github.com/python-rope/rope/blob/master/rope/refactor/rename.py) (python-rope, 2026) · dossier: agent-refactoring-engines G105-F04; eval-v1-calibration E01-F10

### PY-10 — Known gaps in Python engines
- **Rule:** Use basedpyright or pyright for symbol rename and reference counts, not for file or module moves: basedpyright 1.40.1 `willRenameFiles` returns no edits for a cross-directory move and wrong edits for a combined move and rename (issue #1888, open on 2026-09-23). Never use LibCST `RenameCommand` as a symbol rename (in one run it rewrote the importers but not the `def`); keep LibCST for pattern codemods. Do not adopt Bowler (archived). pylsp's built-in rope support covers only rename and completion; use pylsp-rope for extract and inline code actions.
- **Detect:** Before relying on a language server, read its `initialize` capabilities (`renameProvider`, `codeActionProvider.codeActionKinds`, `workspace.fileOperations.willRename`); after any move, run `rg -n -F 'old.module.path' -g '*.py' -g '*.toml' -g '*.cfg' -g '*.ini' -g '*.yaml'`, then the type checker and the tests.
- **Not when:** The LibCST result is one fixture run and Pylance was not tested. In the same runs, rope MoveModule was correct.
- **Tier:** T1 · **Class:** structural · **Fix risk:** medium · **Grade:** B
- **Source:** [basedpyright issue #1888](https://github.com/DetachHead/basedpyright/issues/1888) (2026); [LibCST codemods](https://libcst.readthedocs.io/en/latest/codemods.html) (Meta, 2026); [Bowler README](https://github.com/facebookincubator/Bowler) (2024); [pylsp-rope README](https://github.com/python-rope/pylsp-rope) (2025) · dossier: agent-refactoring-engines G105-F04, G105-F18, G105-F10

### PY-11 — Code actions by exact title; Windows paths and line endings
- **Rule:** Select pylsp-rope code actions by exact kind and exact title ("Extract method including similar statements" is listed before "Extract method"), pass exact ranges, and treat a null, empty or unexpectedly broad WorkspaceEdit, or ERROR lines on the server's stderr, as a failure. On Windows Git Bash, pass engines repo-relative or long-form paths (`cygpath -m -l`), prefix native tools with `MSYS_NO_PATHCONV=1` when an argument starts with `/` or contains `=/` (`--old_name=/pkg/util` reached one program as `C:/Program Files/Git/pkg/util`), and check line endings after every engine edit.
- **Detect:** Assert the expected file and hunk count before applying; `git diff --stat` must match the plan; `git ls-files --eol | rg 'w/mixed'`; a `~` in `echo "$TEMP"` means 8.3 short paths.
- **Not when:** These are single-machine observations (one user whose name has an 8.3 alias; rope preserved CRLF in the same runs), and with `core.autocrlf=true` git may normalise endings at commit. Exact title matching breaks when a server rewords its titles, so pin engine versions.
- **Tier:** T1 · **Class:** structural · **Fix risk:** low · **Grade:** C
- **Source:** [pylsp-rope README](https://github.com/python-rope/pylsp-rope) (2025); [Git for Windows release notes](https://github.com/git-for-windows/build-extra/blob/main/ReleaseNotes.md) (2026); [cygpath](https://cygwin.com/cygwin-ug-net/cygpath.html) (Cygwin, 2026); [git-ls-files](https://git-scm.com/docs/git-ls-files) (Git, 2026) · dossier: agent-refactoring-engines G105-F15, G105-F12

### PY-12 — Census the old name, including strings and reflection, before and after
- **Rule:** Before any rename, move or signature change, save a whole-repo census of the old name (including YAML, JSON, TOML, templates, SQL, `.env.example` and docs) and a reflective-access sweep; after the engine runs, repeat both and explain or hand-fix every surviving hit. A clean type check does not prove behaviour was preserved: rope, basedpyright and Serena all left `getattr(mathx, 'compute_total')` in one fixture run.
- **Detect:** `rg -n -w -F OLD --hidden -g '!.git' > before.txt`; `rg -n 'getattr[(]|setattr[(]|hasattr[(]|__getattr__|import_module[(]|mock[.]patch[(]|globals[(][)]'`; check `mock.patch` targets, importlib strings and pyproject entry points for old module paths; diff `before.txt` against the post-edit census.
- **Not when:** Keep the census a manual-review list rather than an automatic string rename: rope's `docs=True` also renames unrelated literals. In statically typed code without reflection, the residual risk is small.
- **Tier:** T1 · **Class:** structural · **Fix risk:** medium · **Grade:** B
- **Source:** [rope rename.py docstring](https://github.com/python-rope/rope/blob/master/rope/refactor/rename.py) (python-rope, 2026); [An Empirical Study of Refactoring Engine Bugs](https://arxiv.org/html/2409.14610v1) (Wang et al., 2024); [basedpyright issue #1888](https://github.com/DetachHead/basedpyright/issues/1888) (2026) · dossier: agent-refactoring-engines G105-F05, G105-F18

### PY-13 — Gate every engine operation with a type check and the tests
- **Rule:** Treat an engine-applied refactoring as unproven: after every operation, run the type checker (basedpyright or pyright, or the project's own checker), then the tests, then review the diff. Weight review effort extract > inline > move > rename.
- **Detect:** `uv run basedpyright` (or `pyright`, or the project's mypy), then `uv run python -m pytest`.
- **Not when:** The evidence that engines ship bugs comes from Java IDEs: 518 engine bugs in Eclipse, IntelliJ IDEA and NetBeans, 66 (12.7%) of them behaviour changes that no compiler catches, with Extract, Inline and Move the most bug-prone (2024 preprint). No per-operation failure rate exists for rope or basedpyright, and the Python fixtures were deliberately adversarial.
- **Tier:** T1 · **Class:** structural · **Fix risk:** low · **Grade:** A
- **Source:** [An Empirical Study of Refactoring Engine Bugs](https://arxiv.org/html/2409.14610v1) (Wang et al., 2024); [Automated Testing of Refactoring Engines](https://mir.cs.illinois.edu/marinov/publications/DanielETAL07ATRE.pdf) (Daniel et al., 2007) · dossier: agent-refactoring-engines G105-F02

### PY-14 — Diff the public API and moved blocks after structural edits
- **Rule:** After a move, an extract or any structural edit made without an engine, diff the package's public API against the base commit with griffe and review moved code with a block-aware move diff; every reported removal or signature change must be an approved, intended change. Commit exactly one refactoring, with no behaviour change mixed in.

### PY-16 — Whole-project dead code: confidence order, whitelist, dynamic-reference veto

## Language traps

### PY-21 — asyncio: dangling tasks, swallowed cancellation, blocking calls
- **Rule:** `asyncio.create_task`/`ensure_future` results that nothing references (RUF006, not in the 0.16 defaults; flake8-async ASYNC300) get the documented mechanical fix: file them under CC-07 (`lens: "concurrency"`, T1 behavioural, fix risk low), which keeps each task in a set and discards it when done, with a new test. Handlers that swallow `asyncio.CancelledError` (including a bare `except:` or `except BaseException` inside `async def`) without re-raising or calling `uncancel()` restore documented language semantics when fixed: file them under CC-21 (T1 behavioural; a `return` in `finally` under ER-09), whose fix re-raises after cleanup (PC-14; eval-v1-calibration E01-F03). Report blocking work in coroutines without fixing it, since that concurrency fix belongs to a human: sync HTTP (ASYNC210), subprocess calls (ASYNC220–222), `open()` (ASYNC230), `time.sleep` (ASYNC251), CPU-bound code, an unbounded `asyncio.Queue()` or `gather` fan-out.
- **Detect:** `ruff check --force-exclude --select RUF006,ASYNC "${F[@]}"` (also review ASYNC212/240/250; ASYNC211/232 exist only in flake8-async); grep `except (asyncio.)?CancelledError` and `asyncio.Queue()` without maxsize; `PYTHONASYNCIODEBUG=1 python -X dev -m pytest`, then grep for "never awaited", "never retrieved" and "Executing … took" (callbacks slower than 100 ms).
- **Not when:** Moving from `gather` to `TaskGroup` changes behaviour (siblings are cancelled on the first failure, and errors arrive as an ExceptionGroup); `gather(return_exceptions=True)` is legitimate for independent jobs; tiny blocking calls are usually negligible, and `to_thread` brings thread-safety concerns and the default pool's worker cap.
- **Tier:** T2 · **Class:** report-only · **Fix risk:** medium · **Grade:** A
- **Source:** [Coroutines and Tasks](https://docs.python.org/3/library/asyncio-task.html) (PSF, 2026); [Developing with asyncio](https://docs.python.org/3/library/asyncio-dev.html) (PSF, 2026); [RUF006 asyncio-dangling-task](https://docs.astral.sh/ruff/rules/asyncio-dangling-task/) (Astral, 2026); [flake8-async rules](https://flake8-async.readthedocs.io/en/latest/rules.html) (python-trio, 2026); [The Heisenbug lurking in your async code](https://textual.textualize.io/blog/2023/02/11/the-heisenbug-lurking-in-your-async-code/) (McGugan, 2023) · dossier: lang-python T21-F08, T21-F09; eval-v1-calibration E01-F07, E01-F03; eval-v2-calibration E02-F08

### PY-23 — Narrow exception handlers; broad catches only at isolation boundaries
- **Rule:** Replace a bare `except:` (E722), an `except Exception`/`BaseException` that neither re-raises nor records the failure (BLE001), `try/except: pass` (S110) and `try/except: continue` (S112) with the exception types the code can handle, and keep the try body to the code that can raise them. Allow broad catches only at isolation boundaries (request handler, job loop, plugin call), where they log with `logger.exception` or `exc_info=True` and then re-raise or return an explicit failure.
- **Detect:** `ruff check --force-exclude --select E722,BLE001,S110,S112 "${F[@]}"`; `ruff check --force-exclude --preview --select PLW0717 "${F[@]}"` (try bodies over 5 statements); review each broad handler by hand: since Ruff 0.16.0, BLE001 is also silenced when the exception is logged with any logging method other than critical, error and exception, so a clean BLE001 does not prove the handler records the failure.
- **Not when:** A bare `except:` followed by an unconditional `raise` is legitimate (transactional rollback; PEP 760 was withdrawn as not worth its cost); daemons need a top-level catch; narrowing too far turns graceful degradation into crashes. The Bandit scan of 197k PyPI packages (PST 2021) shows the pattern is common, not that it causes harm.
- **Tier:** T1 · **Class:** behavioural · **Fix risk:** high · **Grade:** A
- **Source:** [PEP 8: Programming Recommendations](https://peps.python.org/pep-0008/) (PSF, 2025); [Google Python Style Guide §2.4](https://google.github.io/styleguide/pyguide.html) (Google); [blind-except (BLE001)](https://docs.astral.sh/ruff/rules/blind-except/) (Astral, 2026); [PEP 760 discussion](https://discuss.python.org/t/pep-760-no-more-bare-excepts/67182) (2024); [Ruohonen et al., PST 2021](https://arxiv.org/abs/2107.12699) (2021) · dossier: lang-python T21-F05; eval-v2-calibration E02-F08

### PY-25 — Definition-time binding traps: mutable defaults and late-binding closures
- **Rule:** Replace a mutable default argument or shared mutable class attribute only where the default is mutated, returned or stored on `self`: build it inside the function behind a `None` sentinel, use an immutable default, or use `field(default_factory=...)` in dataclasses. - **Detect:** `ruff check --force-exclude --select B006,B008,RUF008,RUF009,RUF012,B023 "${F[@]}"`; for each default hit, check whether the default escapes or is mutated (if not, the hit is style-only); review callbacks registered in loops (GUI handlers, `call_soon`, thread targets, dispatch dicts).

### PY-30 — Optimise only profiled hot spots; never rewrite idioms for speed
- **Rule:** Change code for performance only on a path a profiler shows is hot, and verify each change with a benchmark. Fix complexity-class problems (list membership in a loop to a set or dict, `pop(0)`/`insert(0, x)` to `deque`, string `+=` in a loop to `''.join`) and per-row loops over numpy, pandas or polars data (`iterrows`, `apply(axis=1)`, `map_elements`, `for i in range(len(arr))`), the latter pinned by golden-output tests. Do not justify Pythonic-idiom rewrites by speed.
- **Detect:** `python -m cProfile -o prof.out <entry>`; `ruff check --force-exclude --select PERF "${F[@]}"` (PERF101/102/402 are defaults; PERF401 and preview PLR6201 are hints; PERF203 is enforced only below Python 3.11); grep hot functions for `.iterrows(`, `apply(.*axis=1`, `map_elements(`, `.pop(0)` and `.insert(0,`.
- **Not when:** Across 54,879 real-project idiom pairs, most rewrites made little difference and some were slower (ICSE 2023), while a synthetic-code study reported large savings (ICPC 2022). A list-to-set change loses order and duplicates and needs hashable elements; truthiness rewrites change semantics for 0, "" and numpy arrays; `iterrows` upcasts int to float64 and numpy integers overflow silently, so vectorised code must match dtypes and NaN handling.
- **Tier:** T1 · **Class:** structural · **Fix risk:** high · **Grade:** B
- **Source:** [Zhang et al., ICSE 2023](https://arxiv.org/abs/2301.12633) (2023); [TimeComplexity](https://wiki.python.org/moin/TimeComplexity) (Python Wiki); [Leelaprute et al., ICPC 2022](https://arxiv.org/abs/2203.14484) (2022); [Enhancing performance](https://pandas.pydata.org/docs/user_guide/enhancingperf.html) (pandas, 2026); [DataFrame.iterrows](https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.iterrows.html) (pandas, 2026) · dossier: lang-python T21-F18, T21-F19; eval-v2-calibration E02-F08

### PY-31 — Complexity rules are a ranked worklist, never a gate
- **Rule:** Report functions over Ruff's default limits (C901 > 10, PLR0912 > 12 branches, PLR0915 > 50 statements, PLR0911 > 6 returns, PLR0913/PLR0917 > 5 arguments or positional arguments, preview PLR1702 > 5 nested blocks), ranked, looking only at the top 5–10%, and calibrate to the project's own distribution. None of these rules is in the 0.16 defaults.
- **Detect:** `ruff check --force-exclude --select C901,PLR0911,PLR0912,PLR0913,PLR0915,PLR0917 --statistics "${F[@]}"`; `ruff check --force-exclude --preview --select PLR1702 "${F[@]}"`.
- **Not when:** No source links these thresholds to Python defect rates; smell prevalence in Python differs sharply from Java (long methods more common, long parameter lists rarer; 32,058,823 lines, 2017). Splitting functions to satisfy counters can hurt readability: GPT-4o refactorings reduced smells but lowered readability (100 ClassEval classes, 2026 preprint). Skip generated code, parsers and state machines.
- **Tier:** T2 · **Class:** report-only · **Fix risk:** high · **Grade:** C
- **Source:** [Ruff settings](https://docs.astral.sh/ruff/settings/) (Astral, 2026); [Vavrová & Zaytsev](https://arxiv.org/abs/1703.10882) (2017); [Midolo et al.](https://arxiv.org/abs/2601.13139) (2026) · dossier: lang-python T21-F17; eval-v2-calibration E02-F08

## Test, mutation and fuzz tooling

### PY-32 — Snapshot quality counts before and after every agent batch
- **Rule:** Before and after each batch, record the Ruff `--statistics` output, the type-checker error count, the S/bandit count, deptry output, the collected test count and pass status, and branch coverage. Revert a batch that raises a count, removes or skips a test, adds a blanket `noqa` or `type: ignore`, widens an `except`, or edits a test to match new behaviour. Refactor only code the tests exercise; otherwise add characterization tests first.
- **Detect:** `uv run pytest --collect-only -q | tail -1`; `uv run coverage run --branch -m pytest && uv run coverage report`; `git diff --name-only | grep -E '(^|/)tests?/'`; grep the diff for `# noqa$`, `type: ignore$`, `pytest.mark.skip` and `except Exception`.
- **Not when:** Agent issue counts mostly scale with churn, and the evidence is single 2026 preprints: in agent-written Python refactoring PRs, 24.17% of modified files gained new Pylint issues and 4.7% new Bandit findings, yet 73.5% of the PRs were merged. Intended behaviour changes need human sign-off, not a looser gate.
- **Tier:** T2 · **Class:** report-only · **Fix risk:** low · **Grade:** B
- **Source:** [Almukhtar et al.](https://arxiv.org/abs/2605.21453) (2026); [Cynthia et al., Beyond Bug Fixes](https://arxiv.org/abs/2601.20109) (2026); [coverage.py: Branch coverage](https://coverage.readthedocs.io/en/latest/branch.html) (Batchelder, 2026); [HN alentred](https://news.ycombinator.com/item?id=49056554) (2026) · dossier: lang-python T21-F24

### PY-33 — Diagnostic runs that turn silent Python warnings into findings
- **Rule:** In the project environment, run the suite once per diagnostic below, in report mode, and record each new warning or error as a candidate: asyncio debug and development mode, EncodingWarning, the 3.14 `finally` SyntaxWarning, and pandas' ChainedAssignmentError (a Warning subclass; on pandas 3.0 and later, chained assignment never updates the frame) and DtypeWarning. On pandas 2.2/2.3, collect warnings from `pd.options.mode.copy_on_write = "warn"` instead.
- **Detect:** `PYTHONASYNCIODEBUG=1 python -X dev -m pytest`; `python -X warn_default_encoding -m pytest`; `python -W error::SyntaxWarning -m compileall src`; `python -W error::pandas.errors.ChainedAssignmentError -W error::pandas.errors.DtypeWarning -m pytest`.
- **Not when:** These runs are diagnostics, not gates: pandas calls CoW warn mode "very noisy" and says only two categories need fixing. Fixing a chained assignment on pandas 3 changes outputs (values that silently stayed stale now update), so route it to the data lens.
- **Tier:** T2 · **Class:** report-only · **Fix risk:** low · **Grade:** A
- **Source:** [Developing with asyncio](https://docs.python.org/3/library/asyncio-dev.html) (PSF, 2026); [PEP 686](https://peps.python.org/pep-0686/) (Inada, 2022); [Copy-on-Write user guide](https://pandas.pydata.org/docs/user_guide/copy_on_write.html) (pandas, 2026); [pandas.read_csv](https://pandas.pydata.org/docs/reference/api/pandas.read_csv.html) (pandas, 2026) · dossier: lang-python T21-F08, T21-F22, T21-F07; data-pipelines-notebooks G109-F03, G109-F10

### PY-34 — Mutation testing: mutmut in WSL2, cosmic-ray natively on Windows
- **Rule:** Run mutmut 3.8.0 only inside WSL2 (it needs `fork` and refuses to run natively), on a clone of the run's repository in the Linux filesystem (PF-21); mutmut 3 mutates only code inside functions. When a native Windows run is required, use cosmic-ray 8.7.0 in a disposable git worktree of the run's repository (PF-21), with an absolute forward-slash interpreter path in `test-command`.
- **Detect:** WSL: `python3 -m venv .venv && . .venv/bin/activate && pip install mutmut==3.8.0 pytest==<x.y.z> && mutmut run "pkg.mod.x_func*" && mutmut results && mutmut show <mutant>`, run inside that clone, with pytest at the version the project locks. Native: a `cfg.toml` with `module-path`, `timeout`, `test-command = "C:/…/.venv/Scripts/python.exe -m pytest -x -q tests"` and distributor `local`, then `cosmic-ray init cfg.toml s.sqlite; cosmic-ray baseline cfg.toml; cosmic-ray exec cfg.toml s.sqlite; cr-report s.sqlite`.
- **Not when:** mutmut's windows-support branch has no timeouts, so infinite-loop mutants hang. cosmic-ray pays one test-process start per mutant (about 0.7 s per mutant, against about 0.01 s for mutmut in WSL; toy projects on one machine). Test setups that are not fork-safe (gevent `patch_all`, grpc, torch) need mutmut's `process_isolation = "forkserver"`.
- **Tier:** T2 · **Class:** report-only · **Fix risk:** low · **Grade:** A
- **Source:** [mutmut README](https://github.com/boxed/mutmut) (boxed, 2026); [mutmut Windows support #397](https://github.com/boxed/mutmut/issues/397) (2025); [Cosmic Ray tutorial](https://github.com/sixty-north/cosmic-ray/blob/master/docs/source/tutorials/intro/index.rst) (sixty-north, 2026) · dossier: mutation-testing-practice G108-F05; eval-v1-calibration E01-F10

### PY-35 — Reject invalid mutation runs before triaging survivors
- **Rule:** Before triaging any survivor, confirm that the unmutated baseline passes (`cosmic-ray baseline`), at least one mutant is killed, INCOMPETENT is 0 unless timeouts on loop code explain it, and timeouts are not clustered; re-run each survivor alone before writing a test for it. Never report "no survivors" from a run that fails these checks.
- **Detect:** `cr-report s.sqlite` (INCOMPETENT count); `mutmut results`; re-run one survivor with `mutmut run "<mutant name>"`; run its covering tests 3 times to rule out flakiness.
- **Not when:** In one toy run, a relative venv path in cosmic-ray's config marked all 23 mutants INCOMPETENT while `cr-report` printed 0% surviving. cosmic-ray marks a mutant incompetent when its test run exceeds the timeout, so genuine infinite-loop mutants land there. The cosmic-ray tutorial warns that results are "essentially useless" when the suite fails without mutations.
- **Tier:** T2 · **Class:** report-only · **Fix risk:** low · **Grade:** B
- **Source:** [Cosmic Ray concepts](https://github.com/sixty-north/cosmic-ray/blob/master/docs/source/concepts.rst) (sixty-north, 2026); [Cosmic Ray tutorial](https://github.com/sixty-north/cosmic-ray/blob/master/docs/source/tutorials/intro/index.rst) (sixty-north, 2026) · dossier: mutation-testing-practice G108-F03, G108-F15, G108-F05

### PY-36 — Scope mutants to the functions about to change; give every survivor a disposition
- **Rule:** Before refactoring, mutate only the functions to be edited (mutmut function globs, `mutate_only_covered_lines`), and widen the scope when tests, fixtures, dependencies or callers change. Give each in-scope survivor one disposition in the triage log under `.harden/`: a killing test in a test-only commit, equivalent with a reachability, infection or propagation argument, unproductive with its arid-class reason (logger calls, for example), or "weakly tested behaviour". The pass never adds mutant skips to the project, in code (`# pragma: no mutate`) or in its config (`do_not_mutate_patterns`): equivalent and unproductive survivors stay as triage-log rows, arid patterns go only into the run configuration of the disposable clone or worktree that PY-34 mutates, and an in-code skip is proposed to the owner. This departs from the dossier's in-code suppression with a reason (mutation-testing-practice G108-F16) because the pass adds no suppressions (PC-08) and project configs are read-only.
- **Detect:** `mutmut run "pkg.mod.x_func*"`; count in-scope survivors with no triage-log row (must be 0); `git diff <base_sha> | grep -E '^\+.*(pragma: no mutate|do_not_mutate_patterns)'` must print nothing; list existing `# pragma: no mutate` lines without a reason as report items; try to falsify an equivalence claim with a bounded Hypothesis differential run of the original against the mutant.
- **Not when:** The per-survivor gate itself is unvalidated (grade D), and so is the four-way disposition (mutation-testing-practice G108-F01, G108-F16); no study validates pre-change scoping as a refactoring gate either. Mutants on the committed lines correlate only weakly with commit-relevant mutants (Kendall/Pearson 0.15–0.4; 25 projects, ICSME 2020), so mutate direct callers too for risky refactors. A log line that carries an audit requirement is not unproductive. A differential run can only refute equivalence, never prove it.
- **Tier:** T2 · **Class:** report-only · **Fix risk:** low · **Grade:** B
- **Source:** [mutmut README](https://github.com/boxed/mutmut) (boxed, 2026); [Commit-Aware Mutation Testing](https://mpapad.github.io/publications/pdfs/ICSME2020.pdf) (Ma et al., 2020); [Practical Mutation Testing at Scale](https://arxiv.org/abs/2102.11378) (Petrović et al., TSE 2022); [Equivalent Mutants in the Wild](https://homes.cs.washington.edu/~rjust/publ/equi_mutants_ems_issta_2024.pdf) (Kushigian et al., 2024); [Prioritizing Mutants to Guide Mutation Testing](https://homes.cs.washington.edu/~rjust/publ/prioritizing_mutants_tcap_icse_2022.pdf) (Kaufman et al., ICSE 2022) · dossier: mutation-testing-practice G108-F01, G108-F02, G108-F12, G108-F16, G108-F18; eval-v1-calibration E01-F10

### PY-37 — Notebooks: check execution order statically, then run a copy with keys absent
- **Rule:** Before trusting or refactoring a notebook, check its JSON (code cells with outputs but a null `execution_count`, non-increasing counts, gaps, absolute paths), then execute it in a fresh clone of the run's repository, in an environment built there from the lock file (PF-21), and compare outputs. Classify each notebook as runs and matches, runs but differs, or fails (NameError suggests hidden state, ModuleNotFoundError dependencies, FileNotFoundError paths). Never execute a notebook that calls live trading or exchange APIs, sends orders, writes to production or spends money without explicit approval; run it with keys absent.
- **Detect:** `jupyter nbconvert --to notebook --execute --ExecutePreprocessor.timeout=600 --output <tmp> nb.ipynb`, or papermill; compare with `pytest --nbval-lax` or `nbdiff`.
- **Not when:** Of 863,878 attempted executions of GitHub notebooks, 24.11% ran without errors and 4.03% reproduced the stored results (MSR 2019); of 10,388 biomedical Python notebooks whose dependencies installed, 1,203 ran and 879 matched (GigaScience 2024). Nondeterministic outputs need sanitisers, and re-execution can be slow.
- **Tier:** T2 · **Class:** report-only · **Fix risk:** low · **Grade:** A
- **Source:** [Pimentel et al., MSR 2019](https://leomurta.github.io/papers/pimentel2019a.pdf) (2019); [Samuel & Mietchen, GigaScience](https://academic.oup.com/gigascience/article/doi/10.1093/gigascience/giad113/7516267) (2024); [nbconvert: Executing notebooks](https://nbconvert.readthedocs.io/en/latest/execute_api.html) (Jupyter, 2026); [nbval](https://nbval.readthedocs.io/en/latest/) (2026) · dossier: data-pipelines-notebooks G109-F16; eval-v1-calibration E01-F10

### PY-38 — Lint notebooks in report mode; never strip outputs or bulk-fix them
- **Rule:** Include `.ipynb` files in lint runs (Ruff 0.6.0 and later lints and formats them by default) and type-check them through nbQA, in report mode only. Do not bulk-format, bulk-fix or strip notebook outputs: saved figures and tables may be the only record of a result. Propose jupytext pairing or nbdime instead.
- **Detect:** `ruff check --force-exclude --output-format concise "${F[@]}"`, confirming that .ipynb files appear (`--show-files`); `nbqa mypy notebooks/`; check `extend-exclude` for `*.ipynb`, `.gitattributes` for `filter=nbstripout`, and `nbstripout --dry-run notebooks/*.ipynb`.
- **Not when:** Notebooks carry 1.4 times more stylistic issues than scripts, partly false positives from notebook idioms (847,881 notebooks, MSR 2022). Stripping outputs is a legitimate team choice some repos already configure; committed outputs can leak secrets or PII, which is a separate security finding.
- **Tier:** T2 · **Class:** report-only · **Fix risk:** high · **Grade:** C
- **Source:** [Ruff configuration: Jupyter notebook discovery](https://docs.astral.sh/ruff/configuration/) (Astral, 2026); [nbQA README](https://nbqa.readthedocs.io/en/latest/readme.html) (2026); [Grotov et al., MSR 2022](https://arxiv.org/abs/2203.16718) (2022); [nbstripout README](https://github.com/kynan/nbstripout) (2026) · dossier: data-pipelines-notebooks G109-F17, G109-F18; eval-v2-calibration E02-F08

### PY-39 — Build a golden-output harness before refactoring dataframe code
- **Rule:** Before refactoring pandas, polars or NumPy pipeline code, or applying NPY201/PD002 (PY-05), capture golden outputs per stage (shape, columns and order, dtypes, null and NaN counts, key uniqueness, numeric min/max/sum/mean, a content hash) and compare after each change with the library's frame assertion at its default tolerances. Run the unchanged code twice first: any difference is nondeterminism to fix before refactoring. Never loosen a tolerance to make a diff pass.
- **Detect:** Look for existing `assert_frame_equal`, `dataframe_regression`, `datacompy` or parquet fixtures; hash with `int(pd.util.hash_pandas_object(df, index=True).sum())`; in polars use `null_count()`, `describe()` and `schema`; compare with `pandas.testing.assert_frame_equal` (rtol 1e-5, atol 1e-8) or `polars.testing.assert_frame_equal`.
- **Not when:** A golden master freezes today's bugs: regenerate it deliberately, with a changelog entry, when a fix is meant to change output. Hashes are order- and dtype-sensitive, so use them as a screen and compare sorted data with tolerances. A clean Ruff run is not evidence of dataframe correctness: Ruff has no rule for merge cardinality, chained assignment, index alignment or look-ahead (see the data lens).
- **Tier:** T1 · **Class:** structural · **Fix risk:** low · **Grade:** B
- **Source:** [pandas.testing.assert_frame_equal](https://pandas.pydata.org/docs/reference/api/pandas.testing.assert_frame_equal.html) (pandas, 2026); [polars.testing.assert_frame_equal](https://docs.pola.rs/api/python/stable/reference/api/polars.testing.assert_frame_equal.html) (Polars, 2026); [pytest-regressions](https://pytest-regressions.readthedocs.io/en/latest/api.html) (ESSS, 2026); [DataComPy](https://capitalone.github.io/datacompy/) (Capital One, 2026); [Refactoring legacy SQL to dbt](https://docs.getdbt.com/guides/refactoring-legacy-sql) (dbt Labs, 2026) · dossier: data-pipelines-notebooks G109-F20, G109-F22

## Evidence limits

- **Versions.** Every version and default here is a 2026-09-23 snapshot (Ruff 0.16.8, mypy 2.3.1 docs, basedpyright 1.40.1, rope 1.14.0, mutmut 3.8.0, cosmic-ray 8.7.0, pandas 3.0.6). Python 3.15 was not yet released.
- **Ruff.** No per-rule precision data exists for the 0.16 defaults; the split between gates and hints rests on official rationale plus Hacker News and GitHub anecdotes (Reddit and Lobsters were not reachable).
- **Engines.** All quantitative engine-bug data is from Java IDEs. The Python engine results are single runs on 2–5-file fixtures on one Windows machine; rope and basedpyright were never cross-validated on real code, and Pylance was not tested.
- **Typing.** The 15% preventable-defect figure is a lower bound from 210 projects; whether annotation coverage in applications lowers defects is open. How PEP 649/749 changes the risk of TC/FA/UP fixes is unverified.
- **Traps.** No study measures how often dangling tasks, swallowed cancellation or blocking calls cause incidents, or what free-threaded CPython does to code that assumes GIL atomicity. No Python study links complexity thresholds to defects.
- **Mutation.** Tool timings come from toy projects on one machine; the per-survivor gate is unvalidated. No Python-specific equivalent-mutant rate was found.
- **Fuzzing.** No Python fuzzing tool is in this file's evidence; Hypothesis appears only as a differential falsification aid (PY-36).
- **Data and notebooks.** dslinter is unmaintained (pins pylint 2.12, Python 3.10 or older) and leakage-analysis needs Python 3.8 (end-of-life): use them only as unvalidated hints in isolated environments. No precision data exists for Ruff's pandas rules.
