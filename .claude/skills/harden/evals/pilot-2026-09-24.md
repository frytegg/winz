# Real-project pilot, 2026-09-24

Target: Orma (XRPL Vault Fragility & Reputation Oracle), a finished hackathon project, run on a disposable local
clone of HEAD `9d2e6ba` (the user's working copy, its uncommitted work and its `.env` were never touched).
Invocation: a separate Claude Code 2.1.281 session, `claude -p "/harden --report-only"`, permission mode
`acceptEdits`, with the user's answers to the skill's questions supplied up front (offline gates in `app/` only,
no XRPL network, registry/advisory lookups allowed). This is the only test of the hooks in a real session: skill
hooks cannot be registered inside evaluation subagents.

## What happened

| Attempt | Outcome | Cause | Action |
|---|---|---|---|
| 1 | Hooks inert; canary FAIL; run stayed report-only; print mode killed 20 running lens subagents after 600 s | The launcher's Git Bash rewrote the `/harden` argument to `C:/Program Files/Git/harden` (MSYS path conversion), so the harness never loaded the skill as a slash command; the agent read SKILL.md from disk | Harness error, not a skill defect. Headless launches from Git Bash need `MSYS_NO_PATHCONV=1`, and `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS=0` so print mode waits for subagents |
| 2 | Every Bash/Edit call refused at the first step; the agent stopped and proposed a fix | **Skill defect.** `CLAUDE_SKILL_DIR` is unset in the hook environment; the `$HOME/.claude/...` fallback reached Windows Python as `/c/Users/...` (path conversion off), Python exited 2 ("can't open file"), and exit 2 means "block" | Fixed in SKILL.md: the launcher converts the path with `cygpath -m` when available and exits 0 when the script is missing (fail open; the canary then fails and the run stays report-only). Regression tests: `scripts/tests/test_hook_command.py` runs the exact frontmatter command |
| 3 | Complete. Canary PASS at start and at stop; hooks refused the Bash and Edit canaries; permission mode recorded (`acceptEdits`) | — | — |

In attempts 1 and 2 the skill behaved as designed: it detected inert or failing guards, stayed report-only,
diagnosed the cause, and refused to route work through subagents to bypass the hooks.

## Attempt 3 results

- Duration 68 min (Preflight 3 min 50 s, Freeze 1 min 21 s, Detect and verify about 50 min, report about 7 min).
- 18 of 19 lenses run; 116 candidates -> 102 findings, 9 questions, 5 rejected with reasons.
- Severities (critical/high/medium/low/nit): 1/12/22/67/1. Critical H-001: server-side request forgery on the public
  `/api/mpt/:id/resolve` route (the server fetches an issuer-written `nav_url` with no destination policy);
  confirmed by the orchestrating session by reading `src/nav.mjs`. Four tool-proven highs (broken `check:*`
  imports, missing `.gitattributes` breaking `deploy.sh` on Windows, a quickstart step needing a git-ignored
  folder, a paper claim contradicted by the team's own filing).
- No tracked file changed, no commit, branch at base; gates (`app/` install, build, lint) green in 3 baseline runs
  and in the fresh clone; `findings.json` valid; SARIF with 116 results plus 6 tool runs.
- Cost: 7.46 M tokens against the run's own 5 M cap (overrun recorded in progress.md); about USD 86 at API prices.
  Attempt 1 cost about USD 105 before being cut. Memory: the launching shell was reaped by Claude Code under
  system memory pressure (several other sessions open); the pilot process itself finished.

## Lessons

1. Test the launcher, not only the script it launches: exit codes of the interpreter collide with hook semantics
   (exit 2 = block).
2. A guard that fails closed on its own infrastructure makes the tool unusable; fail open plus a canary that
   detects inert guards is the safer design, and it worked here.
3. The cost of a full run is high on a 150-file repository; a cheaper first pass (fewer lenses or passes) is
   worth offering when the user's quota is limited.
