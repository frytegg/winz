# First real use: four judged documents, 1 October 2026

The skill had never been applied to anything. This is what happened when it was, on the documentation of a
template entering a bounty where documentation is 30 of 100 points, three days before the deadline.

## What moved

Six agents in two passes produced 202 exact replacements over four documents. Every one was applied through
`scripts/apply_edits.py`, which compares the protected tokens of the text being replaced with those of its
replacement and refuses an edit where a number, a hash, a link or anything in backticks has changed.

| document | words | median sentence | 35 words or more | em dashes /1000 | tier-1 candidates |
|---|---|---|---|---|---|
| `README.md` | 3,521 | 26 → **16** | 30 % → **2 %** | 3.9 → **0.0** | 13 → **0** |
| `docs/hedera-behaviour.md` | 9,696 | 33 → **17** | 46 % → **2 %** | 9.9 → **1.9** | 13 → **0** |
| `docs/use-the-checks-in-your-app.md` | — | 28 → **14** | 40 % → **3 %** | 1.8 → **0.0** | 0 → 0 |
| `docs/troubleshooting.md` | — | 16 → **13** | 15 % → **5 %** | 5.0 → **0.0** | 8 → **0** |
| control corpus | 9,418 | 12 to 18 | 1 % to 5 % | 0.0 to 0.5 | — |

All four finished inside the control band. The repository's own twelve documentation checks passed before and
after, and its 590 offline tests were untouched, which is independent evidence that no fact moved: those checks
resolve every path, link, script name, identifier, environment variable and quoted figure in the prose against
the tree and against the evidence records.

## What the pass taught the skill

### C-01. The number of edits has to scale with the document, and one agent will not say so

The first pass asked each editor for "15 to 40 edits". Every one returned close to 40. For `README.md` at 3,521
words that was enough to land inside the band. For `docs/hedera-behaviour.md` at 9,696 words it moved the median
from 33 to 23 and stopped there, still outside. A second pass on that file alone took it to 17.

**Rule:** ask for roughly **one edit per 120 words**, and say so as a rate rather than a range. A reviewer who is
given a range will return its top.

### C-02. Splitting one document across two agents costs edits at the seam

The second pass gave two agents one half of the file each. 16 of their 99 edits did not apply: the halves
overlapped at the boundary, and the second agent's `old` strings no longer existed because the first agent's
edits had already rewritten that text.

**Rule:** when one document needs more than one agent, give each a region bounded by headings that exist in the
file, and say that the regions do not touch. Or run them in sequence, each on the file as the previous one left
it. Never two agents on overlapping prose.

### C-03. The fact guard compared the wrong thing, and the obvious fix was also wrong

One legitimate edit was refused. Its `old` string began in the middle of an inline code span, so the first
backtick the guard saw was a closing one. It paired that with the next opening backtick and counted the ordinary
prose between two code spans as a protected token.

The obvious fix was to count the backticks and skip the code-span comparison when the count is odd. **That fix
was written, tested, and is wrong.** The snippet that failed holds two backticks, an even number, and still
begins inside a span: parity cannot answer the question, because nothing in a fragment says which of its
backticks opens and which closes.

**What was applied instead:** the guard no longer compares the snippet at all. It applies the edit to a copy of
the whole file and compares the protected tokens of the file before with those of the file after. The file
always knows where its code spans are. Four cases now hold it, in `scripts/tests/test_apply_edits.py`: a plain
rewrite passes, the straddling snippet that used to be refused passes, a quietly altered number is refused, and
a quietly altered identifier is refused.

The lesson is older than this skill: a check that reads a fragment of a structured document will eventually
misread it, and the cheap answer is to check the document.

### C-04. A document written as commands and rules does not drift

`AGENTS.md` was measured with the others and needed nothing: median 16, 11 % of sentences past 35 words, zero em
dashes, zero tier-1 candidates. It is the same project, the same author, the same week as the four that were far
outside the band.

The difference is register. `AGENTS.md` is a command table, a numbered procedure and a list of invariants. The
four that drifted are explanatory prose. **Explanation is where the drift lives**; reference material resists it
by its shape. Measure both, expect to edit one.

### C-05. The checker's thresholds behaved as the control predicted

This is the first evidence that the eleven rules are calibrated rather than asserted. Tier-1 counts went 13 → 0,
13 → 0 and 8 → 0 on the three documents that had them, and the shape measurements moved into the control band at
the same time. No threshold had to be changed during the pass, and no rule fired on a document already inside the
band.

## What is still untested

The claim this pass does **not** support is that the result reads better to a person. Everything above is a
distribution and a checker, and both were defined by this skill. The honest test is a reader who does not know
which version is which, and that has not been run. The next real improvement remains an eval suite in the shape
of `adewale/anti-slop-writing`: blind judges, ablations, and a null hypothesis that the rules change nothing.

Until that exists, the strongest claim available is the one in the table: four documents that sat far outside a
measured human band now sit inside it, without a single fact moving.
